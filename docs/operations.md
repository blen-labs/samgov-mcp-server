# Operations

Use Node 24 LTS. Set the variables in `.env.example` in your hosting platform; do not commit a filled environment file. `scripts/init-env.mjs` generates strong values into a new file with mode 0600 and refuses overwrites. It does not configure Google or a database.

| Setting                                            | Required behavior                                                                        |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `PUBLIC_URL`                                       | Public HTTPS origin only, with no path, query, credentials, or fragment                  |
| `DATABASE_URL`                                     | PostgreSQL connection string; use a private network or validated TLS                     |
| `AUTH_MODE`                                        | `better-auth` by default; optional `external`                                            |
| `BETTER_AUTH_SECRET`                               | Persistent random secret, generated by the setup script                                  |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`         | Configure both; callback is `PUBLIC_URL/account/auth/callback/google`                    |
| `OAUTH_SIGNING_JWKS`                               | Private signing-key set; retain appropriate old public verification keys during rotation |
| `OAUTH_COOKIE_KEYS`                                | JSON array of persistent random signing secrets, newest first                            |
| `ACTIVE_ENCRYPTION_KEY_ID`, `ENCRYPTION_KEYS_JSON` | Active key ID and key ring; each key is exactly 32 bytes, canonical base64               |
| `PORT`                                             | 3000 by default; set by the host in production                                           |
| `TENANT_DAILY_SEARCH_LIMIT`                        | Searches per organization per day; defaults to 1000                                      |

## Organization administration

Run these with the service's private environment. In a local checkout, use `node --env-file=.env dist/manage.js`; in the running production container, use `node dist/manage.js`.

```sh
mkdir -p .local
node --env-file=.env dist/manage.js create-tenant 'Example Organization' admin@example.com .local/new-connector.json
node --env-file=.env dist/manage.js invite TENANT_UUID member@example.com member
node --env-file=.env dist/manage.js list-tenants
node --env-file=.env dist/manage.js list-members TENANT_UUID
node --env-file=.env dist/manage.js disable-member TENANT_UUID ACCOUNT_UUID
node --env-file=.env dist/manage.js revoke-tenant TENANT_UUID
```

New private output paths must not already exist. Securely deliver the generated client configuration only to the intended administrator. Creating an invitation does not send email or grant access to another tenant. Invitations do not overwrite an existing membership's role or re-enable disabled membership.

Google users do not need a password setup link. The optional password path uses `setup-account EMAIL NAME NEW_PRIVATE_FILE`; its single-use link expires in one hour. Deliver it privately. Recovery revokes existing Better Auth login sessions and delegated OAuth grants. No email is sent automatically.

A tenant administrator saves or replaces the SAM.gov key during a fresh consent flow. Saving does **not** prove the key works; run the real search acceptance afterward. Members cannot replace credentials. `disable-member` blocks subsequent tenant access and revokes that user's tenant grants; `revoke-tenant` disables the whole organization. Data is retained, not deleted.

## External JWT mode

`AUTH_MODE=external` disables the built-in login/OAuth broker. Set `OAUTH_ISSUER` and `OAUTH_JWKS_URI` to HTTPS URLs. The external authority must issue RS256 or ES256 tokens with exact issuer, audience `PUBLIC_URL/mcp`, subject, expiry, issued-at time, client ID (`client_id` or `azp`), and space-delimited scopes.

This is an advanced integration. Its operator must provision matching external-issuer/client/subject rows in `tenant_clients` and `tenant_memberships`. The built-in `create-tenant` command creates first-party OAuth clients and does not configure an external identity provider. Read scope is `sam:opportunities:read`. External admin tokens additionally need `sam:credentials:write` and an admin membership to call `POST /admin/credential` with `{"api_key":"..."}`. Never log the request body.

## Rotation, backups, and retention

- Keep encryption keys outside PostgreSQL, in the host's secret store. Back them up securely together with the database recovery procedure. A database backup alone cannot recover encrypted credentials.
- To rotate the key ring, add a new random key and select its ID for new writes. Retain old keys until **all** tenant keys and encrypted OAuth records have been rewritten or expired. Changing only the active ID does not re-encrypt old rows.
- Do not casually regenerate `BETTER_AUTH_SECRET`, signing keys, or cookie keys during a deploy; this can invalidate sessions or make provider credentials unreadable.
- Use host-managed PostgreSQL backups and test restoration in an isolated environment before public production onboarding. Full backup/restore and zero-downtime migrations are not yet acceptance-tested.
- Organization/member revocation retains data. Operators must define deletion and backup retention policies, and separately manage Better Auth session/account retention. The service's expiry cleanup covers OAuth records and rate windows.

## Resource limits and edge configuration

Tool requests are limited to 60 per tenant per minute. Searches are also capped per organization per day (`TENANT_DAILY_SEARCH_LIMIT`, default 1000); reaching the cap logs one `tenant_daily_limit_reached` warning with the tenant ID and never the search arguments. An identical search repeated by the same user more than 5 times in 10 minutes is refused as `REPEATED_CALL`, so a looping assistant cannot drain the quota. That repeat counter lives in process memory, so each replica counts separately and search arguments are never stored. OAuth traffic is limited to 120 requests per socket IP per minute. Behind a reverse proxy, many users can share that IP and quota: the application intentionally does not trust caller-supplied forwarding headers. Configure trusted-edge per-client rate limits and size/time limits, and load-test your deployment before broad rollout. No aggregate global concurrency limit is currently implemented.

Only the configured public host and local/health-check hosts are accepted. Cross-origin browser requests to `/mcp` are rejected. Inspector's local backend and remote non-browser MCP clients can connect without browser CORS. The app must remain behind HTTPS; native loopback callback URIs are reserved for operator-registered development clients.

## Troubleshooting

| Result                 | Meaning and next step                                                           |
| ---------------------- | ------------------------------------------------------------------------------- |
| HTTP 401 from `/mcp`   | Missing/invalid/expired/revoked token; restart client authorization             |
| HTTP 403               | Wrong scope, inactive membership, tenant, or missing stored key                 |
| HTTP 429               | Service quota reached; respect `Retry-After`                                    |
| `KEY_REJECTED`         | SAM.gov returned 401/403; check the SAM.gov account key and permissions         |
| `RATE_LIMITED`         | SAM.gov quota reached; wait before retrying                                     |
| `UPSTREAM_ERROR`       | Upstream non-success status; a 404 is not proof of a bad key or an empty search |
| `UPSTREAM_UNAVAILABLE` | Network failure, redirect rejection, timeout, or cancellation                   |
| `INVALID_RESPONSE`     | Invalid, oversized, or contradictory upstream response; no results confirmed    |
| `DAILY_LIMIT`          | Organization daily search cap reached; wait `retry_after` or raise the limit    |
| `REPEATED_CALL`        | Same search repeated too often; change the arguments or stop retrying           |

A daily **SAM.gov API drift** workflow runs one search and checks the response shape and core fields. It fails on a format change or a rejected key and only warns during SAM.gov outages. It needs the repository secret `SAM_GOV_MONITOR_API_KEY`; without it, the run is skipped with a warning.

Check `/healthz` for process health, protected-resource metadata for discovery, Inspector OAuth for authentication, and `npm run test:deployed` for real data. These are separate gates. The October 8, 2026 empty SAM.gov HTTP 404 reproduced on both a local machine and Railway; current account-key verification is still pending. Do not work around that failure by treating it as successful empty data.

Disable logging of authorization headers, cookies, token requests, consent bodies, and outbound SAM.gov query strings. The upstream API requires `api_key` in the URL. Application errors deliberately suppress raw upstream bodies and exception details.
